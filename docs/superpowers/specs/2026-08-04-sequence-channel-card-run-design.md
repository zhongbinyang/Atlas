# Sequence Channel Card Run Design

## Goal

Improve the sequence-run channel overview so one card no longer stretches across the full page and every channel can start an isolated run directly from its card.

## Current Behavior

- Every selected channel has a persistent card and the whole card opens that channel's detail view.
- The card container declares grid columns but is missing `display: grid`, so one card occupies the full available width.
- The top-level run action uses the current checkbox selection and already sends `channel_indexes` to the existing sequence-run endpoint.
- There is no per-card run action.

## Approved Interaction

Each card keeps two distinct actions:

1. Clicking the card body or `查看详情 →` opens the channel detail view.
2. Clicking `运行此通道` runs only that card's channel.

The per-card action sends exactly one channel index and does not change the checkbox selection in the top run controls. The button stops click propagation so it never opens the detail view accidentally.

The card run button is available on the initial cards before any run starts. It is disabled when the queue is empty or while any sequence run is active. Starting a card run uses the existing global run lock, progress polling, abort action, result reset, error handling, and final response handling. Because the backend has one shared execution slot, all card run buttons and the top run button are disabled together during execution.

## Layout

The channel container becomes an explicit CSS grid.

- Desktop tracks are approximately 20–24rem wide and aligned from the left.
- Additional cards fill subsequent columns and wrap naturally.
- One card remains card-sized instead of expanding across the page.
- Cards in the same row stretch to a consistent height.
- Below the existing mobile breakpoint, the grid becomes one full-width column.

The card keeps its header, current status, progress, counts, and timing. Its existing bottom affordance becomes an action row with a primary `运行此通道` button and a secondary `查看详情 →` action. The card may become slightly shorter, but no current information is removed.

## Frontend Architecture

The existing run flow is shared rather than duplicated:

- A small pure helper resolves the requested channel indexes. A card run supplies `[channelIndex]`; the top run supplies the current checkbox selection.
- `runSequence` accepts an optional explicit channel list and builds the same `/api/sequence/run` payload used today. The top-level click listener calls it through a zero-argument wrapper so the browser `Event` object can never be mistaken for a channel list.
- The card button calls the shared run function with its channel index.
- `setSeqControlsDisabled` updates card run buttons as part of the global sequence lock.
- Card rerenders retain the existing whole-card focus behavior. Interactive descendants are excluded from the card's Enter/Space detail shortcut so button keyboard activation cannot trigger navigation.

No backend endpoint, request schema, queue persistence, result schema, or channel-selection state changes are required.

## Error and Edge Cases

- Empty queue: card run buttons are disabled and no request is issued.
- Active run: repeated card or top-level run requests are ignored by the existing `seqRunning` guard.
- Missing/disabled channel: no card is rendered by the existing channel projection; an explicit invalid index is not generated by the UI.
- Busy and network failures use the existing messages and restore all run controls in `finally`.
- Per-card runs still render every configured channel card; only the requested channel receives live/result data.

## Accessibility

- `运行此通道` is a native button with an accessible label that includes the channel name.
- The button has a visible focus state and a disabled state.
- The card remains keyboard-openable with Enter/Space when the card itself is focused.
- Button clicks and key activation do not bubble into the card detail action.
- Status remains expressed with text, not color alone.

## Verification

- Node behavior test: an explicit card channel produces a literal one-item `channel_indexes` payload without mutating the selected channels.
- Node behavior test: the top run path retains its current selected-channel behavior.
- Static UI contract: card action button and event isolation are present.
- Static UI/CSS contract: the container is an explicit grid with bounded desktop tracks and a one-column mobile rule.
- Existing channel-card, polling, detail, and workspace tests remain green.

## Out of Scope

- Running multiple ad-hoc channels from card buttons.
- Per-channel abort controls.
- Concurrent sequence executions.
- Backend or API changes.
- Editing channel selection from inside a card.
