# 序列运行页布局优化设计

日期：2026-08-04
状态：已确认，进入实现

## 目标

将 Agent「序列运行」页调整为操作员优先的信息层级：首屏先看到总体状态与通道进度，需要时再展开工程详情；当前阶段从页面中删除 SN 与工单输入。

## 已确认范围

- 删除运行页的 SN、工单控件，前端不再向 `POST /api/sequence/run` 提交这两个字段。
- 后端请求/响应模型暂不删除字段，保留兼容性，避免影响已有 API 调用方和步骤内读取 SN 的能力。
- 将当前队列摘要升级为紧凑运行摘要，集中显示运行状态、步骤数、模板绑定和通道选择。
- 保留通道 × 步骤矩阵作为首屏主视图；步骤表头带序号，首尾列固定，状态统一使用中文。
- 全部成功时默认收起完整报告；失败、错误或中止时自动展开报告并聚焦第一个异常步骤。
- 底部运行栏重组为“通道选择”和“状态 + 运行操作”两组。
- 报告继续保留通道页签、限值、实测值和原始 JSON，不修改执行结果数据结构。

## 页面结构

```text
页面标题 / 去编排
运行摘要：状态 + 队列/模板 + 已选通道
通道进度矩阵（首屏主视图）
查看完整报告按钮
按需展开的通道报告
固定运行栏：通道选择 | 总体状态 | 开始/重新运行 | 中止
```

## 状态规则

- `pass`、`ok` → 通过
- `fail`、`failed` → 失败
- `error` → 错误
- `running` → 执行中
- `waiting_resource` → 等待资源
- `skipped` → 跳过
- `aborted` → 已中止

状态必须保留文字，不只依赖颜色。

## 交互规则

1. 进入运行页时显示当前队列步数、模板绑定和已选通道数量。
2. 点击开始后清空旧结果，摘要与底栏切换为“执行中”。
3. 进度轮询持续刷新矩阵，不自动展开完整报告。
4. 全部成功后显示“通过”，报告保持收起，并提供“查看完整报告”。
5. 存在失败、错误或中止时，报告自动展开到第一个异常通道/步骤。
6. 点击矩阵的通道或步骤单元格仍可主动打开对应报告。

## 非目标

- 不新增运行历史、导出、趋势统计。
- 不实现从失败步骤继续执行或只重跑单步。
- 不重构多通道执行、资源锁或中心数据库。
- 不删除后端 SN、工单字段。

## 验证

- 静态 UI 测试锁定新 DOM、删除的控件、请求载荷和响应展示行为。
