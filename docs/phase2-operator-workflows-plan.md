# Atlas 第二批操作效率与前端基础能力优化计划

## 目标

在第一批稳定刷新、后台指标采样和移动端热修的基础上，提升值班人员和
机台操作员的日常操作效率。本批只使用现有 HTTP API，不改变部署方式：

1. 调度中心可以快速判断机台态势，并按名称、地址和状态定位机台。
2. 调度中心不再使用原生 `alert()` / `confirm()`，弹窗可用键盘完整操作。
3. Agent 的 VI 工作台明确呈现“路径、参数、试跑、命名、注册”阶段，
   防止未查询参数时误试跑或误注册。
4. 两端静态页面不依赖外部字体，并提供 favicon。

## 用户与页面任务

- 值班人员：在调度中心发现异常机台、筛选目标机台、执行截图和文件操作。
- 机台操作员：在 Agent 页面查询 VI 参数、编辑输入、试跑并注册到中心。
- 本批不改变序列主从布局；序列工作台的详情抽屉留到下一批。

## 设计方向

### 视觉令牌

- 雾蓝背景 `#dce4ec`
- 面板白 `#f7fafc`
- 激光青 `#0a6e7a`
- 成功绿 `#1a7f4b`
- 告警橙 `#b86a00`
- 错误红 `#b33a2b`
- 品牌/正文/数据字体统一使用本地系统字体栈，不请求外部字体。

### 布局

调度中心使用一条紧凑的“机台遥测控制带”，将摘要和筛选放在同一操作
上下文内，而不是堆叠通用大数字卡片：

```text
┌ 总数 12 │ 在线 9 │ 忙碌 2 │ 离线 1 ── [搜索] [状态] [排序] ┐
└───────────────────────────────────────────────────────────┘
┌ 机台卡 ┐  ┌ 机台卡 ┐  ┌ 机台卡 ┐
```

Agent VI 工作台用真实流程顺序组织界面，阶段编号只表达业务顺序：

```text
[1 路径] ─ [2 参数] ─ [3 试跑] ─ [4 命名] ─ [5 注册]
┌ 路径与名称 ──────────────┐  ┌ 当前阶段/下一步 ┐
├ 参数表 ──────────────────┤  └─────────────────┘
└ 试跑结果 / 原始 JSON ────┘
```

### 交互特征

- 调度中心控制带是本批唯一强调性视觉元素，其余面板保持克制。
- 状态同时使用文字和颜色，不只依赖颜色。
- VI 阶段轨由真实状态驱动，不作为装饰。
- 动画仅用于 Toast 进入和阶段状态变化，并遵循
  `prefers-reduced-motion`。

## 全局约束

- 不实现认证与鉴权。
- 不改变现有 HTTP API 路径、请求字段、响应字段或状态码。
- 不引入 React、Vue、包管理器或新的运行时依赖。
- 保持第一批的 2000 ms 可见页刷新、无重叠、隐藏暂停和 keyed DOM 行为。
- 请求失败时保留最近一次成功数据。
- 不使用外部字体或其他公网静态资源。
- 所有新增控件具有可访问名称和清晰的 `:focus-visible` 状态。
- 页面主要流程可用键盘完成；对话框打开后聚焦、Esc 关闭、关闭后恢复焦点。
- 危险操作必须使用自定义确认对话框，不使用原生 `confirm()`。
- 成功、失败和加载反馈不得互相覆盖。
- 所有行为变更测试先行，先观察预期失败，再写最小实现并观察通过。

## Task 1：调度中心通知、对话框与离线静态资源

### 范围

- 修改 Scheduler 的 `index.html`、`style.css`、`app.js`，
  可扩展 `dashboard-runtime.js` 和 Node 测试。
- 增加 `role="status"` 的 Toast 区域：
  - 成功和可恢复失败使用中文消息；
  - 同一时间只显示一个 Toast；
  - 默认 4000 ms 自动关闭；
  - 鼠标或键盘聚焦时暂停自动关闭；
  - 不取代模板页面已有的持久 operation/load 消息。
- 用统一对话框控制器管理截图、历史、文件、预览和危险确认：
  - `role="dialog"`、`aria-modal="true"`、标题关联；
  - 打开后聚焦首个可操作控件；
  - Tab/Shift+Tab 焦点循环；
  - Esc 关闭；
  - 关闭后恢复到触发控件；
  - 同时只允许一个对话框处于打开状态。
- 用自定义确认对话框替代三个模板删除的 `confirm()`。
- 用 Toast 或对话框内行内错误替代文件、截图和历史的 `alert()`。
- 顶部导航为当前页面设置 `aria-current="page"`。
- 删除两端 Google Fonts 引用，改为本地系统字体栈。
- 为两端增加可由现有静态目录直接提供的 SVG favicon。

### TDD 与验收

1. Node 测试先覆盖对话框焦点进入、循环、Esc、焦点恢复和异步确认结果。
2. 静态资源测试先断言无 `fonts.googleapis.com`、存在 favicon、
   对话框语义和 Toast live region。
3. 实现后运行 Scheduler Node 测试、Scheduler/Agent 静态 UI 测试和
   `cargo test --workspace`。
4. Chrome 验证无 `/favicon.ico`、Google Fonts 请求和控制台错误。

## Task 2：调度中心机台遥测控制带

### 范围

- 在机台网格上方增加紧凑摘要与过滤控制：
  - 总数、在线、忙碌、离线；
  - 名称/IP/端口搜索；
  - 全部、在线、忙碌、离线状态筛选；
  - 名称、状态、CPU、内存排序；
  - “仅异常”开关；
  - 最近刷新时间和自动刷新状态。
- 摘要基于最近一次成功的 Agent 数组计算，不增加 API 请求。
- 过滤和排序只改变展示集合，不修改 `agents` 原始顺序或数据。
- 筛选结果仍按 Agent ID keyed reconcile，匹配卡片节点继续复用。
- 过滤后为空时区分“暂无机台”和“没有匹配机台”。
- Agent 详情将“最近见面”改为“最后心跳”，显示相对时间和本地时间；
  无效时间显示 `—`。
- 自动刷新只更新摘要、刷新时间和可见卡片，不重置搜索、筛选、排序或焦点。
- 控制带在 640 px 以下改为多行布局，不产生页面级横向滚动。

### TDD 与验收

1. Node 测试先覆盖摘要、组合筛选、异常筛选、四种排序及不修改输入数组。
2. 静态 UI 测试先覆盖控件可访问名称、空状态和移动端安全布局。
3. 自动刷新回归测试确认过滤状态不变、匹配卡片节点身份保持。
4. Chrome 使用模拟多机台数据验证搜索、筛选、排序、空状态和两个刷新周期。

## Task 3：Agent VI 阶段式工作台

### 范围

- 新增职责单一、可独立测试的 `workbench-runtime.js`，管理 VI 编辑状态：
  - `empty`：没有有效路径；
  - `ready_to_inspect`：有路径，尚未查询；
  - `inspecting`：正在查询；
  - `ready_to_run`：参数查询成功；
  - `running`：正在试跑；
  - `ready_to_register`：试跑成功且名称有效；
  - `registering`：正在注册；
  - `registered`：注册成功。
- 路径变化后立即使旧参数和旧试跑结果失效；仅失焦时规范化路径和默认名称，
  不自动发请求。
- 查询成功前禁用“试跑”和“注册到中心”，并显示原因。
- 请求期间禁用相关输入和按钮，阻止重复查询、试跑和注册。
- 参数查询成功后展示入参/出参数量；试跑成功后展示简要结果，并保留可展开
  的原始 JSON 与复制按钮。
- 将“前面板”和“超时”放入默认折叠的“高级设置”。
- 注册成功后提供“查看已注册功能”和“继续编辑副本”。
- 中心 VI 列表增加名称、ID、来源机台和路径的客户端搜索。
- 保持现有 API payload 与模板加载行为；从中心加载模板后进入
  `ready_to_run`，不要求重新查询。

### TDD 与验收

1. Node 测试先覆盖状态转换、路径变化失效、按钮启用条件和重复提交保护。
2. Agent 静态 UI 测试先覆盖阶段轨、高级设置、结果摘要/复制和搜索控件。
3. 实现后运行新增 Node 测试、`cargo test -p agent` 和 workspace 测试。
4. Chrome 使用受控 API 响应验证：
   - 未查询时不能试跑或注册；
   - 查询、试跑和注册期间不能重复提交；
   - 路径变化清除旧状态；
   - 成功流程到达 `registered`；
   - 390、768、1440 宽度无页面级横向溢出；
   - 键盘可完成完整流程。
